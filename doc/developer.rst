pvng for developers documentation
=========================================

How to Contribute
-----------------------------------------

Contributions of any kind (code, documentation, bug reports) are more than welcome.

Coding conventions
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Code is written in TypeScript. Style is enforced by Prettier (``.prettierrc.json``: 2-space indent, single quotes, semicolons, 80 character print width) and ESLint (``eslint.config.js``), rather than by hand. In doubt, just look at the existing code, and check your changes with:

.. code-block:: bash

  npm run lint
  npm run typecheck

Commits
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Use descriptive commit messages using the following format:

 - a short single-line summary, e.g. "add transparency for mesh and line geoms". This line summary should not exceed 60-70 characters.
 - optionally a block of text that describes the change in more detail, e.g.

      color information is now stored as an RGBA quadruplet to accomodate one 
      alpha value for each vertex. Coloring operations have grown the ability to 
      specify alpha values. In case they are omitted, they default to 1.0 
      (fully opaque) structure.

   the block should be wrapped at 80 characters.

In case you are submitting a larger feature/bugfix, split your work into multiple commits. The main advantage is that your change becomes easier to review.

Before submitting
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Before submitting, or sending the pull request

 - make sure that there are no unrelated changes checked in.
 - run ``npm run lint``, ``npm run typecheck``, ``npm test`` and ``npm run test:browser`` locally; these are the same checks CI (``.github/workflows/ci.yml``) runs on every push and pull request.
 - in case you are adding new functionality, make sure you are adding it to the API documentation.
 - don't check in changes to ``dist/`` or ``dist-debug/``. They're build output (gitignored) and are regenerated by ``npm run build``.



How to release a new version of pvng
------------------------------------------

These are the steps to release a new version of pvng:

Release Testing
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

* Check that CI is green on the commit you intend to release (lint, typecheck, build, unit tests, browser tests)
* Check that the samples in the documentation work
* Check that all samples in the demo work
* Check that the release notes contain all major changes
* Update version number

    - Update version number in release notes (README.md)
    - Update version number in package.json
    - Update version number in doc/conf.py

Release Publishing
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

* Publish the package to npm: ``npm publish`` (this runs ``npm run build`` automatically via the ``prepublishOnly`` script)
* Tag the release using ``git tag v$version -m "tagging v$version"``
* Push the tag: ``git push origin v$version``
* Create a GitHub release from the tag
